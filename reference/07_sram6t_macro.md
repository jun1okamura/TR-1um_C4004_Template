# 6T SRAM マクロ構成 — Scratchpad 64bit + スタック 48bit + レジスタ

作成: 2026-09-20 / **更新: 2026-09-20（ビットセル 604 µm²/bit に圧縮・センスアンプ採用を反映 → `08_senseamp_refs.md`）** / 前提: `05_cell_circuits.md` §4、`06_design_policy.md`、
先行試作（12T ラッチ型レジスタアレイ `REG8x16`）の実測結果

---

## 0. 先に結論

1. **マクロは1本にまとめる。`C4004_SRAM32X4`（32 word × 4 bit = 128 bit）。**
   Scratchpad 16word と スタック 12word（4段 × 3ニブル）は
   **どちらも 4bit 単位**なので、同じアレイに同居できる。別マクロを2つ作る理由がない。
2. **ACC / IR / SP / ステートカウンタ等はマクロに入れない。FF のまま残す（29 bit）。**
   単一ポートなので、毎サイクル同時にアクセスされるものを入れると破綻する。
3. ~~センスアンプを作らない~~ → **方針変更（2026-09-20）: センスアンプを設計する。**
   速度のためには不要（750 kHz に対し BL フルスイングは 23 ns で 1000 倍の余裕）だが、
   **BL 振幅を落として消費電力とリードディスターブを減らす**目的で採用する。
   トポロジ・文献・設計目標は **`08_senseamp_refs.md`**。
   本命は **US4910713A（DEC, 1988/1990）の高入力インピーダンス・ストローブ型差動ラッチ**。
   16 cell / BL の規模ではレプリカ列は不要で、`DEL` セルによる固定遅延で `SE` を作れる。
4. **ただし面積の得は小さい。** 128 bit という規模では周辺回路がアレイと同じだけ食う:

   | | アレイ | 周辺 | マクロ計 |
   |---|---:|---:|---:|
   | **6T SRAM**（604 µm²/bit 確定） | 0.085 mm² | 0.162 mm² | **0.272 mm²** |
   | 12T TLAT（TD4実績） | 0.169 mm² | 0.112 mm² | **0.281 mm²** |

   セルは 2.0 倍小さいのに、**プリチャージ・カラム MUX・内部タイミング生成**が
   ほぼ同じだけ増えて相殺する（差は 3.9 %）。
   → **面積だけが理由なら 6T にする意味はない。**
   6T を選ぶ理由は「SRAM の設計・検証を一度通しておく」こと自体に置くべき。
   第一シリコンの確実性を取るなら TD4 で実証済みの 12T TLAT を流用する。

## 1. マクロの単位化

### 1.1 なぜ 4bit 幅に揃うか

| ブロック | 元の姿 | 4bit ワードで見ると |
|---|---|---|
| Scratchpad（インデックスレジスタ R0–R15） | 16 × 4 bit | **16 word** |
| アドレススタック（PC + 3段） | 4 段 × 12 bit | **12 word**（4段 × 3ニブル） |
| 合計 | 112 bit | **28 word** |

4004 は元々 **A1/A2/A3 の3ステートで PC を下位→中位→上位の順にニブル単位で出す**。
つまりアドレススタックは本質的に「3ニブルの並び」であって、
12bit 幅のレジスタとして持つ必要がない。**4bit 幅アレイと相性が完全に一致する。**

28 word を 32 word に切り上げて **32 word × 4 bit = 128 bit**。アドレス 5 bit。

### 1.2 アドレスマップ

| `A[4:0]` | 内容 |
|---|---|
| `00`–`0F` | Scratchpad R0–R15（`A[3:0]` = レジスタ番号） |
| `10`–`1B` | アドレススタック: `A = 0x10 + L*3 + N`（`L`=段 0–3, `N`=ニブル 0–2） |
| `1C`–`1F` | 予備 16 bit（スキャン観測用 / 将来の拡張 / テストパターン格納） |

スタックのアドレス生成: `{1'b1, SP[1:0], NIB[1:0]}` 形式にすると
`L*3+N` の乗算が要る。**`A = 0x10 + (N<<2) + L` に並べ替えれば連結だけで済む**
（`A = {1'b1, NIB[1:0], SP[1:0]}`、`NIB=3` は未使用）。
こちらを採る。使うのは 12 word ではなく `10`–`1B` のうち `NIB≤2` の 12 個。

## 2. マクロに入れないレジスタ（FF のまま残す）

単一ポート SRAM は **1 サイクル 1 アクセス**。以下は他のアクセスと同時に
読み書きされるので、入れてはいけない。

| レジスタ | bit | 理由 |
|---|---:|---|
| `ACC` + `CY` | 5 | ALU と毎サイクル往復する |
| `IR`（`OPR`/`OPA`） | 8 | M1/M2 で取り込み、X1–X3 の間ずっと参照され続ける |
| `SP`（スタックポインタ） | 2 | アレイのアドレスを作る側。アレイの中には置けない |
| ステートカウンタ | 3 | A1..X3 を生成。常時動く |
| CM-RAM バンク | 3 | X2/X3 で出力しながら別アドレスを読む可能性がある |
| 制御・テンポラリ（DB ラッチ、キャリー保持、TEST 等） | 8 | |
| **計** | **29** | TG-DFF(16T, 3,500 µm²) × 29 = **0.102 mm²** |

> `SRC`（RAM アドレス）は 4004 では **CPU 側で保持しない**（X2/X3 で送出し、
> 4002 側がラッチする）ので、レジスタとして持つ必要はない。

予備ワード `1C`–`1F` は「同時アクセスが起きないもの」なら入れてよいが、
**第一シリコンでは空けておき、スキャン観測用に使う**ことを推奨。

## 3. 6T ビットセルの設計

### 3.1 回路とサイジング

```
        WL ─────────┬───────────────────────┬─────
                    │                       │
                  ┌─┴─┐ AX_L           AX_R ┌─┴─┐
        BL ───────┤   ├──●─────────────●────┤   ├─────── BLB
                  └───┘  │             │    └───┘
                      ┌──┴──┐       ┌──┴──┐
                 PU_L │ p   │       │  p  │ PU_R      (vdd)
                      ├─────┤ ><    ├─────┤
                 PD_L │ n   │       │  n  │ PD_R      (vss)
                      └──┬──┘       └──┬──┘
                         Q             QB
```

| Tr | 型 | W / L | 役割 |
|---|---|---|---|
| `PU_L` / `PU_R` | PMOS | **3.4 / 1.0**（最小） | プルアップ |
| `PD_L` / `PD_R` | NMOS | **6.8 / 1.0** | プルダウン |
| `AX_L` / `AX_R` | NMOS | **3.4 / 1.0**（最小） | アクセス |

- **セルレシオ CR = PD/AX = 6.8/3.4 = 2.0** → リードディスターブに対し十分
  （一般に CR ≥ 1.5）。TR-1um は `AN.WM` の Wmin = 3.4 µm と粗いので、
  **CR を作れる最小の組合せがこれ**（3.4 と 6.8）。
- **プルアップレシオ PR = AX/PU = 3.4/3.4 = 1.0（幅比）**。ただし
  移動度が NMOS `u0`=0.0668 / PMOS `u0`=0.0197 と **3.4 倍**違う
  （`models_IP62_mos_v2.lib` 実測値）ので、実効的には AX が PU に十分勝ち、
  書込みは通る見込み。
  ただし NMOS は `vsat`=135.5k と PMOS の 700k より大幅に低くモデル化されており、
  5 V での実効比は u0 比ほど開かない。**PR は必ず SPICE で確認すること**（§10.1）。
  マージンが足りなければ **`PU` の L を 1.4–2.0 µm に伸ばす**
  （幅は変えない = セル寸法が動かない）。
- 電源 5 V、`Vth_n = +0.763 V` / `Vth_p = −0.678 V` なので保持 SNM は潤沢。

### 3.2 セル寸法 — **実設計値 30.6 × 22 µm（2026-09-20 確定）**

| | 横（WL 方向） | 縦（BL 方向） | 面積 | µm²/Tr |
|---|---:|---:|---:|---:|
| **実設計（圧縮後・確定）** | **27.45 µm**※ | **22.0 µm** | **604.0 µm²/bit** | **100.7** |
| 実設計（初版） | 30.6 µm | 22.0 µm | 673.2 µm²/bit | 112.2 |
| 当初見積り | 22 µm | 28 µm | 616.0 µm²/bit | 102.7 |

※ 面積 604 µm² は確報。高さ 22 µm 据え置きとして幅を逆算した値。
初版 30.6 µm から **−10.3 %** 圧縮された。当初見積り 616 µm² を **−1.9 %** 下回る。

縦 22 µm は `AN 6.8 + AN.WN 5.0 + WN.AP 7.0 + AP 3.4 = 22.2 µm` の
**ウェル規則の積み上げそのもの**で、これ以上縮まない。
横 30.6 µm は 4 トランジスタ列 = 7.65 µm/列。見積りの 5.0 µm/列より広いのは
BL/BLB + 電源の M1 トラックを通すため。

**µm²/Tr は 100.7。** TD4 の 12T TLAT（110 µm²/Tr）を下回り、
「約 100–110 µm²/Tr」がこのプロセスのカスタムアレイの密度限界と見てよい。
6T は TLAT(1,320 µm²/bit) に対し **2.19 倍小さい**。

> 以降は **横 = WL 方向 30.6 µm / 縦 = BL 方向 22.0 µm** として計算している。
> もし逆（横 22 / 縦 30.6）なら §4.1 の表と §4.3 のピッチ整合の話が入れ替わる。

> n-well の規則（`WN.W1` 8.0 / `AP.WN` 7.0 / `AN.WN` 5.0 / `WN.S1` 12.0）が
> 縦方向を支配する。**well はアレイ全体を貫く横ストライプにして
> ミラー行対で共有**すること。1セルずつ well を切ると 2 倍以上に膨らむ。

## 4. アレイ構成

### 4.1 行×列の取り方

32 word × 4 bit をどう折るか:

| 構成 | アレイ寸法（タップ行込み） | 縦横比 | BL 負荷 | 行デコーダ | カラム MUX |
|---|---|---:|---:|---|---|
| 32 行 × 4 列 | 122.4 × 788 µm | 0.16 | 32 cell | 5→32 | 不要 |
| **16 行 × 8 列** | **219.6 × 388 µm** | **0.57** | **16 cell** | **4→16** | **2:1** |
| 8 行 × 16 列 | 489.6 × 188 µm | 2.60 | 8 cell | 3→8 | 4:1 |

**16 行 × 8 列 / 2:1 カラム MUX を採用。** 理由:

- 行デコーダが **4→16**。TD4 の `DEC16`（`DEC0`/`DEC2` から構成）が
  そのまま流用でき、面積も実測値 52,960 µm² が使える。
- BL 負荷 16 cell は TD4 の `REG8x16` と同じ。**読出し時間の実測値
  23 ns がそのまま参考にできる。**
- アスペクト比が素直（**219.6 × 388 µm、0.57:1**）でフロアプランに収まりやすい。

アドレス割当: 行 = `A[3:0]`、カラム選択 = `A[4]`。
つまり **偶数ワードが左カラム群、奇数ワードが右カラム群**。
§1.2 のマップは `A[4]` が「Scratchpad(0) / スタック(1)」の区別になるので、
**アレイの左半分が Scratchpad、右半分がスタック**という綺麗な分割になる。

### 4.2 2層メタルでの配線（ここが最大の制約）

M1/M2 しかないので、電源の走らせ方を先に決める。

| 層 | 方向 | 用途 |
|---|---|---|
| **M1** | 縦 | `BL` / `BLB` / **`VDD` / `VSS` 縦ストラップ** |
| **M2** | 横 | `WL` のみ |

- 1 セルあたり M1 は 4 トラック（BL, BLB, VDD, VSS）。
  M1 pitch = 1.8 + 1.4 = 3.2 µm → 4 × 3.2 = 12.8 µm。
  **実セル幅 27.45 µm に対し 14.6 µm の余裕がある**ので、
  VSS を 2 本に増やす／BL を太くして抵抗を下げる、といった選択肢が取れる。
- **M2 は WL 専用**。横方向の電源リングは張れないので、
  **M1 の縦ストラップをアレイ上下端でまとめて外へ出す**。
- サブストレートタップ / n-well タップは **4 行ごとにタップ行を挿入**。
  タップ行を 12 µm とすると 16 行で 3 本 → **352 → 388 µm**。
  5 V プロセスなのでラッチアップ余裕を見るなら **2 行ごと（タップ間隔 44 µm）**
  にしてもよい（+84 µm、アレイ 244.8 × 436 µm）。SPICE ではなく
  プロセス側の推奨タップ間隔を確認すること。
- `WN` はアレイを貫く横ストライプ（§3.2）。`WN.S1` = 12.0 µm があるので
  **well を分断しない**こと。

### 4.3 行ピッチ 22 µm と標準セル行高 62.6 µm の不整合 ★要対処

**これが実設計値が出て初めて見えた最大の実装課題。**

アレイの行ピッチは **22 µm**。一方 TR-1um 標準セルの行高は **62.6 µm** で、
**2.85 倍**ある。つまり **行デコーダと WL ドライバを標準セルでピッチ合わせできない。**

| 案 | 内容 | 評価 |
|---|---|---|
| (a) **WL ドライバだけカスタム** | 22 µm ピッチの INV 2 段（4T）を自分で描く。デコード出力 16 本は標準セルブロックから配線チャネル経由で受ける | **◎ 推奨**。描くのは 4T × 16 と小さい |
| (b) デコーダごとカスタム | 4→16 を 22 µm ピッチで全部描く | 面積は最小だが工数が大きい |
| (c) 2 列に折る | 偶数行／奇数行で 2 列に分け、各列 44 µm ピッチ | まだ 62.6 µm に届かない。不可 |
| (d) 3 列に折る | 各列 66 µm ピッチ ≥ 62.6 µm | 標準セルが使えるが、配線が 3 系統に散る |

**(a) を採る。** デコーダ本体（`DEC16`、52,960 µm²）はアレイ横の標準セルブロックに置き、
その 16 本の出力を **M1 の縦チャネル（16 × 3.2 = 51.2 µm）**でドライバ列まで引く。
ドライバ列は 22 µm ピッチのカスタムセル 16 個。

> TD4 の `REG8x16` は TLAT セルが 40 µm 高だったのでこの問題が目立たなかった。
> 6T にしてセルを縮めた副作用として出てきたコストであり、
> **「6T は面積で得しない」という結論をさらに補強する。**

## 5. 周辺回路

| ブロック | 構成 | 面積 |
|---|---|---:|
| 行デコーダ 4→16 | `DEC16`（TD4 流用） | 52,960 µm² |
| WL ドライバ ×16 | **22 µm ピッチのカスタム INV 2 段（4T）** — §4.3 | 8,000 µm² |
| プリチャージ / イコライズ | 8 BL 対 × 3T（PMOS 2 + EQ 1）、ピッチ合わせ | 6,000 µm² |
| カラム MUX 2:1 | 8 対 × TG 2 個 | 8,000 µm² |
| ライトドライバ ×4 | INV + TG 対 | 8,000 µm² |
| **センスアンプ ×4** | ストローブ型差動ラッチ（US4910713A 系）+ 出力ラッチ。入力対は W=20.4/L=2.0 で大きく取る → `08_senseamp_refs.md` | 24,000 µm² |
| 内部タイミング生成 | `DEL1/2/4` + ゲート（`PRE`/`WL`/**`SE`**/`WEN`、§6） | 55,000 µm² |
| **小計** | | **161,960 µm² = 0.162 mm²** |

- **センスアンプあり**（方針変更）。差動ラッチ型を 2 カラム（54.9 µm）ピッチに収める。
  **レプリカ列は不要** — `SE` は `WL` 立上りからの固定遅延（`DEL2` 数段）で作る。
  入力対のオフセット（~20 mV）に対し BL 差動 **200 mV** を目標とする。
- **カラム MUX は読み書き共用**。`A[4]` で TG を開く。
- プリチャージ PMOS は **W=6.8 程度**（BL を 1 サイクル以内に VDD まで戻す）。
  16 cell ぶんの BL 容量（TD4 実測の系列から数十 fF）なら余裕。

## 6. 内部タイミング（単相 CLK から自己生成）

外部は `CLK` 1 本（`06_design_policy.md` の単相方針）。
マクロ内部で **リード → ライトの読出し変更書込み（RMW）を 1 サイクルで**行う。

```
CLK      ‾‾‾‾‾‾‾‾‾\______________/‾‾‾‾‾‾‾‾‾‾‾\_______
PRE      ______/‾‾‾‾‾‾\______________________/‾‾‾‾‾‾\    CLK↓で開始、DEL2 幅
WL       ____________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\__________    PRE 解除後に立上げ
DOUT     ──────────────< 有効 >───────────────────────    WL 後 ~23 ns
WEN      ______________________/‾‾‾‾‾‾‾‾‾‾\____________  CLK↓ (後半) で書込み
```

| 信号 | 生成 |
|---|---|
| `PRE` | `CLK` 立下りから `DEL2`（~8.8 ns）幅のパルス |
| `WL` | `PRE` 終了後に `CE` と行デコード出力の AND で立上げ、次の `CLK` 立下りまで保持 |
| `WEN` | `WE & ~CLK`（サイクル後半のみ）。`WL` は開いたままなので書込みが成立 |

- **サイクル前半 = リード、後半 = ライト。** 外部は単相のまま
  読出し変更書込みができる（PC の +1 がこれで 1 ステートに収まる）。
- 750 kHz なら 1 ステート = 1.33 µs。リード 23 ns、プリチャージ 10 ns 程度なので
  **タイミング余裕は 50 倍以上**。`DEL` セルの精度で十分。
- ライト中に `DOUT` が変化しないよう、**リード結果はマクロ外でラッチ**する
  （`DOUT` はレベルセンス出力。`06_design_policy.md` の DLATCH を使う）。

## 7. アクセススケジュール（1 マシンサイクル = 8 ステート）

| ステート | アクセス | 内容 |
|---|---|---|
| `A1` | RMW | `read A=0x10+{0,SP}` → PC ニブル0 を D バスへ → +1 → write back |
| `A2` | RMW | ニブル1 → 出力 → +carry → write back |
| `A3` | RMW | ニブル2 → 出力 → +carry → write back |
| `M1` | — | 命令上位ニブル取込（IR は FF） |
| `M2` | — | 命令下位ニブル取込 |
| `X1` | R / RMW | Scratchpad 読出し（`A={0,OPA}`） |
| `X2` | R / W | ALU 結果書戻し、または SRC 上位送出 |
| `X3` | W / RMW | 書戻し、`JMS` なら スタック push、`BBL` なら pop |

- **インクリメンタは 4bit 1個だけ**でよい（ニブル直列にキャリーを送る）。
  12bit インクリメンタ（約 0.04 mm²）が不要になる。
  キャリーは FF 1 bit（§2 の「制御・テンポラリ」に含む）。
- `JMS`: `SP` を +1 してから A1–A3 で新 PC を書く。
  戻り番地は既に `SP` 旧値の 3 ワードに残っている（インクリメント済み）。
- `BBL`: `SP` を −1 するだけ。アレイへのアクセスは不要。
- **同時アクセスは発生しない**ので、単一ポートで足りる。

## 8. マクロ I/F

```
.subckt C4004_SRAM32X4  A[4:0] DIN[3:0] DOUT[3:0] WE CE CLK vdd vss
```

| ピン | 方向 | 説明 |
|---|---|---|
| `A[4:0]` | in | ワードアドレス。`A[3:0]`=行、`A[4]`=カラム選択 |
| `DIN[3:0]` | in | 書込みデータ。サイクル後半に取り込む |
| `DOUT[3:0]` | out | 読出しデータ。**レベルセンス**（`WL` が開いている間有効） |
| `WE` | in | 1 = サイクル後半に書込み |
| `CE` | in | 0 = `WL` を上げない（プリチャージのみ）。非アクセスステートで下げる |
| `CLK` | in | 単相クロック。内部で `PRE`/`WL`/`WEN` を生成 |

`CE=0` のステート（M1/M2）で **BL を確実にプリチャージし切る**設計にしておくと、
アクセスが飛び飛びでも安定する。

### 10.1 セル単体（SPICE / 最優先）

## 11. 判断のまとめ

| | 6T SRAM | 12T TLAT（TD4実証済） |
|---|---|---|
| マクロ面積 | **0.272 mm²**（SA 込み） | 0.281 mm² |
| セル面積 | **604 µm²/bit（実設計・圧縮後）** | 1,320 µm²/bit |
| 周辺 | プリチャージ・カラムMUX・タイミング生成 + **22µmピッチのカスタムWLドライバ**（§4.3） | デコーダとドライバのみ（標準セルで足りる） |
| 比設計 | **要**（CR/PR、SNM 検証） | 不要（ratioless） |
| 読出し | レベルセンス（プリチャージ必要） | 組合せ（素通し） |
| 実績 | 無し | **REG8x16 で実測・Liberty 化済** |
| 流用性 | 大容量化したときに効く | 128bit 級で完結 |

**面積だけを見るなら 6T にする理由は薄い**（差 3.3 %、0.009 mm²）。
セルを 604 µm² まで圧縮してもこの結論は変わらなかった
（縮めたぶんがセンスアンプとタイミング生成に回るため）。
6T を採るのは「TR-1um で SRAM を一度成立させる」こと自体に価値を置く場合。
セル寸法は確定したので、**次は §10.1 の SPICE マージン検証**
（保持/リード SNM、ライトマージン、リードディスターブ、70 ℃ 保持リーク）と、
**センスアンプの設計**（→ `08_senseamp_refs.md`）。
ここが通れば 6T で進める判断ができる。

リスクを取らないなら、**`REG32x4` として TD4 の TLAT アレイを 4bit 幅に
作り直すのが最短**（デコーダ・ドライバ・Liberty 化フローがそのまま使える）。
